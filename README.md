## Overview

**EmotionSense AI** is a full-stack platform designed to help educators, counselors, and parents understand a student's emotional and academic state through a structured AI-driven live video interview.

The student logs in, selects their preferred language, fills out a 6-step pre-session form, and then enters a live video session where:

1. Personalized interview questions are generated by the **Sarvam AI** language model.
2. Questions are **spoken aloud** to the student using Sarvam's neural Text-to-Speech engine.
3. The student's answers are **transcribed** in real time via Sarvam's Speech-to-Text engine.
4. After the session, a full **analysis report** is generated (strengths, concerns, emotional signals, engagement score) and **emailed** in the student's own language to their parent and mentor.

Everything — the UI, questions, and the final report — adapts to the student's chosen language: **English, Hindi (हिन्दी), Bengali (বাংলা), or Odia (ଓଡ଼ିଆ)**.

## Key Features

### 🔐 Authentication
- Secure **register / login / logout** flow with bcrypt-hashed passwords.
- Session-based authentication stored in MongoDB via `connect-mongo`.
- A `ProtectedRoute` component guards `/language-select`, `/setup`, and `/interview` — unauthenticated users are redirected to `/login` and returned to their original destination after signing in.

### 🌐 Multilingual UI (4 Languages)
- Full interface translation across **English, Hindi, Bengali, and Odia**.
- Language is chosen on a dedicated **Language Selection Page** before the form begins.
- All form labels, placeholders, validation errors, instructions, consent texts, and interview questions adapt instantly.
- Form state (e.g. `comfortLevel: "Very Comfortable"`) remains in English for consistent backend processing — only the display layer changes.
- The selected language persists in `sessionStorage` for the duration of the session.

### 📋 6-Step Pre-Session Form
Each step is a focused, animated screen with full dark pink glassmorphism styling:

| Step | Title | What it collects |
|------|-------|-----------------|
| 1 | Basic User Information | Name, age, gender, email, phone, institution, student ID |
| 2 | Language & Session Preferences | Interview language, comfort level, session duration, session purpose |
| 3 | Emotional State Quick Survey | Stress, confidence, and personal comfort levels (1–5 sliders) |
| 4 | Technical Readiness Check | Camera access, microphone access, internet stability, live preview |
| 5 | Consent & Authorized Contacts | 4 consent checkboxes + parent/guardian and mentor contact details |
| 6 | Pre-Session Instructions | Guidelines + AI voice assistant (reads instructions aloud, answers questions) |

### 🎥 Live Interview Session
- Full **video recording** via `MediaRecorder` API.
- AI generates **8 personalized questions** based on the student's form data (name, purpose, language, emotional state).
- Questions are **spoken aloud** by Sarvam TTS (`bulbul:v3` model).
- Student answers are **recorded and transcribed** using Sarvam STT (`saarika:v2.5` model).
- Session timer, question navigation (skip, replay), and a real-time transcript are shown.
- Falls back to pre-written questions in the correct language if Sarvam is unavailable.

### 📊 AI Report Generation & Email Delivery
- After the session, a full structured report is generated using the Sarvam LLM (`sarvam-m` model).
- The report includes:
  - Session summary (duration, questions answered, engagement score)
  - Strengths, concerns, and action items
  - Emotional signals (stress level, confidence level, camera comfort)
  - Communication style and emotional overview
  - Follow-up priority (low / medium / high)
- The report is emailed in **the student's own language** to their **parent** and **mentor** via Nodemailer (supports Gmail SMTP and OAuth2).
- Falls back to a rule-based report if the AI is unavailable.

### 🎨 Design System
- Consistent **dark slate-950 background** with animated **pink glow blobs** (`SoftBackdrop`).
- Glassmorphism cards (`bg-white/[0.04] backdrop-blur-md border-white/[0.08]`).
- Pink (`#ec4899`) as the primary accent throughout — buttons, progress bars, focus rings, selected states.
- Smooth animations powered by **Framer Motion** and page scroll by **Lenis**.

## Getting Started

### Prerequisites

- **Node.js** v20 or higher
- **npm** v9 or higher
- A running **MongoDB** instance (local or MongoDB Atlas)
- A **Sarvam AI** API key — [get one at sarvam.ai](https://sarvam.ai)
- A **Google Gemini** API key — [get one at aistudio.google.com](https://aistudio.google.com)
- A Gmail account configured for SMTP or OAuth2 (for email reports)

### Installation

**1. Clone the repository**

```bash
git clone https://github.com/shubhamraj82/EmotiSense-AI.git
cd EmotiSense-AI
```

**2. Install backend dependencies**

```bash
cd backend
npm install
```

**3. Install frontend dependencies**

```bash
cd ../frontend
npm install
```

### Environment Variables

#### Backend — create `backend/.env`

```env
# Server
PORT=5000
NODE_ENV=development

# MongoDB
MONGODB_URI=mongodb://localhost:27017/emotisense

# Session
SESSION_SECRET=your_super_secret_session_key_here

# Sarvam AI
SARVAM_API_KEY=your_sarvam_api_key_here
SARVAM_API_BASE_URL=https://api.sarvam.ai        # optional — this is the default
SARVAM_CHAT_MODEL=sarvam-m                        # optional — this is the default
SARVAM_TTS_MODEL=bulbul:v3                        # optional — this is the default
SARVAM_STT_MODEL=saarika:v2.5                     # optional — this is the default
SARVAM_TTS_SPEAKER=shubh                          # optional — this is the default

# Email (choose one of the two options below)

# Option A — Gmail App Password (simpler)
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USER=your_gmail@gmail.com
EMAIL_PASS=your_gmail_app_password

# Option B — Gmail OAuth2 (more secure, recommended for production)
EMAIL_USER=your_gmail@gmail.com
GMAIL_CLIENT_ID=your_google_oauth_client_id
GMAIL_CLIENT_SECRET=your_google_oauth_client_secret
GMAIL_REFRESH_TOKEN=your_google_oauth_refresh_token
```

#### Frontend — create `frontend/.env`

```env
# Backend API base URL
VITE_BASE_URL=http://localhost:5000
VITE_API_BASE_URL=http://localhost:5000

# Google Gemini (for the pre-session AI voice assistant in Step 6)
VITE_GEMINI_API_KEY=your_gemini_api_key_here
```

> ⚠️ **Never commit `.env` files.** Both `.gitignore` files already exclude them.

### Running the Project

**Start the backend** (from the `backend/` directory):

```bash
npm run server
```

The API server starts on `http://localhost:5000`.

**Start the frontend** (from the `frontend/` directory):

```bash
npm run dev
```

The React app opens on `http://localhost:5173`.

**Build for production:**

```bash
# Frontend
cd frontend && npm run build

# Backend
cd backend && npm run build
```

## API Reference

All API routes are prefixed with their respective base paths.

### Auth — `/api/auth`

| Method | Route | Auth Required | Description |
|--------|-------|:-------------:|-------------|
| `POST` | `/register` | ✗ | Register a new user. Body: `{ name, email, password }` |
| `POST` | `/login` | ✗ | Log in. Body: `{ email, password }` |
| `GET` | `/verify` | ✓ | Verify the current session. Returns `{ user }` |
| `POST` | `/logout` | ✓ | Destroy the current session |

### AI — `/api/ai`

| Method | Route | Auth Required | Description |
|--------|-------|:-------------:|-------------|
| `POST` | `/interview-questions` | ✗ | Generate 8 personalized interview questions using Sarvam LLM. Falls back to hardcoded questions if API is unavailable. Body: full form data object |

### Sarvam — `/api/sarvam`

| Method | Route | Auth Required | Description |
|--------|-------|:-------------:|-------------|
| `POST` | `/tts` | ✗ | Text-to-Speech. Body: `{ text, languageCode }`. Returns `audio/wav` |
| `POST` | `/stt` | ✗ | Speech-to-Text. Body: `{ audioBase64, mimeType, languageCode }`. Returns `{ transcript, languageCode }` |
| `POST` | `/chat` | ✗ | Chat completion. Body: `{ systemPrompt, messages[] }`. Returns `{ answer }` |

### Reports — `/api/reports`

| Method | Route | Auth Required | Description |
|--------|-------|:-------------:|-------------|
| `POST` | `/interview` | ✗ | Generate full interview analysis report from transcript + form data. Emails report to parent & mentor. Body: `{ formData, transcript[], durationSeconds }` |

## Internationalization (i18n)

EmotionSense AI supports **four languages** natively. The system is built on a flat key-value translation table.

### Supported Languages

| Code | Language | Script |
|------|----------|--------|
| `en` | English | Latin |
| `hi` | Hindi | देवनागरी |
| `bn` | Bengali | বাংলা লিপি |
| `or` | Odia | ଓଡ଼ିଆ ଲିପି |

### How It Works

```
frontend/src/lib/i18n/
├── locales.ts        — UILocale type, UI_LOCALES array, parseStoredLocale()
└── translations.ts   — ~550-line flat message table for all 4 locales

frontend/src/context/
└── LocaleContext.tsx — LocaleProvider + useLocale() hook
```

The `useLocale()` hook exposes:
- `locale` — current `UILocale` code
- `setLocale(locale)` — switch language and persist to `sessionStorage`
- `t(key, vars?)` — translate a key, with optional `{variable}` interpolation

Example usage inside any component:

```tsx
const { t } = useLocale();

<label>{t('step1.fullName')}</label>
<input placeholder={t('step1.phFullName')} />
<p>{t('form.stepOf', { current: 2, total: 6 })}</p>
```

**Important:** Form state values (e.g. `"Very Comfortable"`, `"Self-assessment"`) are always stored in **English** regardless of the selected language. Only the displayed text is translated. This ensures the backend always receives consistent, predictable values.

The **backend report engine** also includes its own copy map (`REPORT_COPY` in `ReportRoute.ts`) so the emailed report matches the student's chosen language — independent of the frontend.

## Authentication

Session-based authentication is implemented with:

- **`express-session`** — server-side sessions with a 7-day cookie lifetime.
- **`connect-mongo`** — sessions stored in MongoDB (collection: `session`).
- **`bcrypt`** (rounds: 10) — passwords hashed before storage, compared on login.
- **`ProtectedRoute`** (frontend) — wraps protected pages and redirects unauthenticated users to `/login`, saving the intended destination in `location.state.from` for post-login redirect.
- **`protect` middleware** (backend) — checks `req.session.isLoggedIn` and `req.session.userId` before allowing access to protected endpoints.

### Session Cookie Settings

| Setting | Value |
|---------|-------|
| `maxAge` | 7 days |
| `httpOnly` | `true` |
| `secure` | `true` in production |
| `sameSite` | `'lax'` |

## Report Generation

When a session ends, `POST /api/reports/interview` receives:
- The student's full **form data** (name, age, institution, language, emotional survey scores, consent contacts)
- The full **transcript** (array of `{ question, answer }` pairs)
- The **session duration** in seconds

The report builder then:

1. **Calculates engagement metrics** — words per answer, answered/skipped questions, engagement score (0–100).
2. **Extracts themes** from answers — progress mentions, support mentions, stress indicators, etc.
3. **Calls Sarvam LLM** to generate a narrative report (summary, strengths, concerns, action items, communication style, emotional overview).
4. **Falls back** to a deterministic rule-based report if the AI call fails.
5. **Builds an HTML email** in the student's language using the `REPORT_COPY` map.
6. **Delivers the email** to the parent and mentor addresses supplied in Step 5 — supports both Gmail App Password (SMTP) and Gmail OAuth2.

### Report Structure

```json
{
  "student": { "name", "institution", "preferredLanguage", "purpose" },
  "summary": "Narrative paragraph about the session...",
  "strengths": ["...", "..."],
  "concerns": ["...", "..."],
  "actionItems": ["...", "..."],
  "engagementScore": 82,
  "emotionalSignals": {
    "stressLevel": 3,
    "confidenceLevel": 4,
    "cameraComfort": "Somewhat Comfortable"
  },
  "communicationStyle": "Detailed and reflective",
  "emotionalOverview": "Student appeared calm and engaged...",
  "followUpPriority": "low"
}
```
